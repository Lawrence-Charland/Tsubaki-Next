## 用法

```
tsubaki sum [选项] <算法> <文件|目录>...
tsubaki verify [选项] <校验和文件|->   （`-` 表示 stdin，需要 -u）
tsubaki cmp [选项] <左清单> <右清单>
tsubaki algo <算法>
tsubaki --help
tsubaki --version
tsubaki --algorithm
tsubaki --completions
```

子命令是必需的：`sum` 计算校验和，`verify` 复核 `sum` 写出的结果文件，`cmp` 比较
两份这样的结果文件，`algo` 说明单个算法。这四个名字是契约：拼法不再变，也不会被
别的东西顶替。`algo-info` 仍然当作 `algo` 的旧长拼法接受，但不带任何承诺，随时可能
消失；要用的名字是 `algo`。

只有 `--help`、`--version`、`--algorithm`（`-a`）和 `--completions`（`-C`）不需要
子命令；子命令位置上换成别的词会按未知子命令报错。这四个通用开关在校验之前检查，
所以也优先于其它参数错误：`tsubaki -a junk` 照样打印算法表并退出 0。同时给出多个时，
`--help` 优先于 `--version`，两者又都优先于 `--algorithm`，而它又优先于
`--completions`。

下文直到 [校验](#校验) 都在讲 `sum`；`verify` 复用同一份校验和文件格式以及
`-v`、`-t`、`-k`、`-K`、`-o`、`-u` 这几个选项。`cmp` 复用同一份格式，但它要两份文件，
而且只接受 `-o` 和 `-c`。`algo` 不要选项，也不要文件，只收一个
算法名。

`算法` 是位置参数，它后面的输入也是。输入可以是目录、文件，或者 `-`（标准输入），
可以混着写。

建议的写法是：算法放最前，然后一口气写完全部输入源，最后再写选项。

```sh
tsubaki sum sha256 目录1 文件2 - -e build -l old.txt
```

选项要放最后，是因为分离写出的值会从开关后面紧跟的普通参数里取，直到队列里的下一个
开关为止：把 `-e` 写在输入前面，它就会把这些输入一并吞掉。`files` 在 `excludes`
和 `lists` 之后才评估，所以这两项筛剩下的路径仍会走到它。

输入一个都不给也行：`tsubaki sum sha256` 会以一条空流跑完，只打印报告块，各计数
全为 0。

### 算法

`none` 只列文件不计算，所有文件都计入 `Not hashed`。其余名字要么是普通摘要，要么
是密钥哈希。

普通摘要：

```
md5  sha1  sha224  sha256  sha384  sha512  sha3_256  sha3_512
blake2b512  blake2s256
```

密钥哈希：

```
hmac_md5  hmac_sha1  hmac_sha224  hmac_sha256  hmac_sha384  hmac_sha512
hmac_sha3_256  hmac_sha3_512  blake2b512_mac  blake2s256_mac
```

`hmac_*` 是"前缀后面那个摘要的 HMAC"，所以 `hmac_sha3_512` 就是 HMAC-SHA3-512。
`blake2b512_mac` 和 `blake2s256_mac` 是带密钥的 BLAKE2b-512 与 BLAKE2s-256；带密钥
的 BLAKE2 与不带密钥的 `blake2b512`/`blake2s256` 结果不同，因为密钥参与了压缩函数。

密钥算法不给密钥会按命令行错误处理：退出码 64，并提示 `needs a key`。给普通摘要
配密钥则只是警告，密钥被忽略。

摘要与 `openssl dgst -<名字>` 一致，HMAC 与 `openssl dgst -<摘要> -hmac <密钥>`
一致，BLAKE2 MAC 与 `openssl mac -macopt key:<密钥> BLAKE2BMAC`（或 `BLAKE2SMAC`）
一致。输出是小写十六进制，长度由算法决定。

`tsubaki -a`（`--algorithm`）把同一批名字打成两列表格（`ALGORITHM`、`KEYED`）。
有 provider 模块被加载时，后面还会跟一张 `ALGORITHM`、`KEYED`、`EXTRA ARGS`、
`SOURCE` 表，见下一节。

`tsubaki algo <算法>` 把同一批事实按单个名字打出来：
一行 `Source:`（内建是 `built-in`，动态算法是提供它的模块路径），然后是摘要宽度、
密钥格式，以及一小段说明。provider 的名字也能查；模块没导出可选的
`tsubaki_algo_info()` 时显示“No information provided.”。自己声明了参数的 provider
（见下文）还会把它的 ArgParser 脚本原样打印在 “ArgParser script:” 之下，模块接受
哪些开关，直接从模块本身就能看出来。

### 动态算法

不在内建清单里的算法可以由动态库（shared object）提供。把目录写进
`TSUBAKI_DYNAMIC_PROVIDER_PATHS`，用 `:` 分隔；每个目录会被递归遍历，扩展名恰好是
`.so` 的文件才会被加载（`libx.so.1` 会被跳过）。空段直接忽略。

现成的 provider 在
[Tsubaki-Sample-Providers](https://github.com/Lawrence-Charland/Tsubaki-Sample-Providers)
里，一个 CMake 工程全包：直接拉取、编译，里面的动态算法就能拿来用，具体有哪些
算法以那个仓库的 README 为准。想看清契约被编译成什么样，看它最快，自己写
provider 也可以直接照抄。

不是自己构建的模块，放进 `TSUBAKI_DYNAMIC_PROVIDER_PATHS` 之前值得先看一眼：

```sh
tsubaki -a                  # 加载了哪些，各自来自哪个路径
tsubaki algo blake3         # 宽度、密钥、说明，以及它将占用的开关
```

`algo` 会打印模块路径；provider 声明了参数时，还会把接受的整份脚本原样打出来
——足以看出路径是不是你想要的那份、它会占用哪些开关。遵守契约的 provider 还会在同一
段文本里写明自己的项目或网址；上面那行 `Source:` 是 tsubaki 自己加的，只会写路径。
它是**加载了模块**才回答的，所以它告诉你模块声称什么，而不是它是否可信。

- **名字能用在哪。** 所有接受算法名的地方，包括 `verify` 的 `-u`。内建名字永远
  优先：模块自报的名字若是内建算法，加载时就被拒掉并打印出文件名，根本进不了表，
  所以 `.so` 抢不走 `sha256`。
- **密钥。** 带密钥的 provider 索取密钥的方式与内建密钥算法一致（`needs a key`，
  退出码 64）。
- **额外的命令行参数。** 需要文件之外参数的算法可以自己声明开关，`tsubaki
algo <名字>` 会把说明这些开关的脚本原样打印出来。开关写在算法名之后，
  `verify` 会把不认识的参数转发下去，所以 `verify -u shake128 file.sum -L 128`
  同样可用；provider 的开关先于 `tsubaki` 自己的选项匹配，因此不能复用后者的
  字母。清单只记算法名，不记这些参数：`-L 128` 不会写进清单，`verify` 也不会从
  清单推断出来。复核得在命令行上原样再给一遍；漏给或给错，模块就按默认值另算
  一份，所有条目都会变成 changed。
- **出错会怎样。** 路径不是可读目录、某个 `.so` 加载不了、少了符号：各打一行
  `Error:` 到 stderr 然后跳过，都不改变退出码。模块与进程同寿，没有任何地方会卸载
  它们。

自己写 provider——要导出哪些符号、摘要缓冲的上限、编译要求、参数脚本的语法——见
[PROVIDER-ABI.zh-cn.md](PROVIDER-ABI.zh-cn.md) 和
`include/dynamic_provider_header.hpp`。

`--algorithm` 会把找到的模块单列一张表：

```
---------- Dynamic providers ----------
ALGORITHM          KEYED  EXTRA ARGS  SOURCE
blake3             NO     NO          /home/user/lib/tsubaki/blake3.so
cshake128          NO     YES         /home/user/lib/tsubaki/cshake128.so
```

`SOURCE` 是模块路径，所以同一个算法的两份旧构建分处两个目录时，一眼就能看出重复。
`EXTRA ARGS` 为 `YES` 表示模块导出了 `tsubaki_need_more_args()`，有自己的命令行
参数；具体接受哪些，用 `tsubaki algo <名字>` 打印的那份脚本看。行的顺序先按
这一列，再按 `KEYED`，最后按名字，所以不需要额外参数的模块排在前面。

### 选项

| 选项                            | 含义                                                                                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `-h`, `--help`                  | 打印帮助后退出                                                                                                                            |
| `-V`, `--version`               | 打印版本后退出                                                                                                                            |
| `-a`, `--algorithm`             | 打印算法列表、每个是否带密钥、provider 是否接受额外参数，以及它来自哪个模块，然后退出                                                     |
| `-C`, `--completions`           | 打印一行供 shell 补全用的词表，然后退出；不需要子命令                                                                                     |
| `-v`, `--verbose`               | 在 stderr 上显示实时进度                                                                                                                  |
| `-t<n>`, `--thread=<n>`         | 工作线程数，正整数，默认为硬件并发数（取不到时用 1）                                                                                      |
| `-k<key>`, `--key=<key>`        | 密钥算法的密钥；普通算法会警告并忽略                                                                                                      |
| `-K<file>`, `--key-file=<file>` | 从 `<file>` 读密钥（`-` 表示 stdin），字节原样；普通算法忽略                                                                              |
| `-T`, `--text`                  | 把密钥文件（或 `-K -` 的 stdin）当文本读：CRLF 折成 LF、尾部行尾去掉，孤立 CR 保留；普通算法忽略                                          |
| `-o<file>`, `--output=<file>`   | 结果写入 `<file>`（新建或截断），而不是 stdout（`sum`）、`<校验和文件>.verify`（`verify`）或 `<左>_to_<右>.cmp`（`cmp`）；`-` 表示 stdout |
| `-u<algo>`, `--use-algo=<algo>` | 用 `<algo>` 校验，而不是清单里的 `Algorithm:` 头（仅 `verify`）                                                                           |
| `-c`, `--canonical`             | 比较前把两边路径变成绝对路径、解析软链接并规整分隔符，仅 `cmp` 使用                                                                       |
| `-e<path>`, `--exclude=<path>`  | 遍历目录时跳过 `<path>` 及其下所有内容，可重复。                                                                                          |
| `-l<file>`, `--list=<file>`     | 从 `<file>` 读取 `"<校验和> <路径>"` 清单，可重复                                                                                         |
| `-s`, `--follow-symlinks`       | 跟随指向目录的符号链接                                                                                                                    |
| `-f`, `--force-rescan`          | 重算输入列表中已有的校验和                                                                                                                |

`verify` 接受 `-v`、`-t`、`-k`、`-K`、`-T`（`--text`）和 `-o`，含义与 `sum` 相同，
另外用 `-u` 指定算法。它没有算法和文件位置参数，也不接受 `-e`、`-l`、`-s`、`-f`：
路径、不给 `-u` 时的算法以及无条件重算都来自校验和文件。这份清单也可以写成 `-`，
从 stdin 读；但那样就没法先读出 `Algorithm:` 头，所以 `-` 输入必须配 `-u`。

`cmp` 只接受 `-o` 和 `-c`。它完全不计算哈希，所以没有算法、密钥、线程或扫描类
选项；`-v`、`-t`、`-k`、`-K`、`-T`、`-e`、`-l`、`-s`、`-f` 都会按命令行
错误拒绝，退出码 64。它的两个位置参数是要比较的结果文件，不是待计算的路径。

### 选项的取值

赋值都按通常写法：长选项用 `=`，短选项可以粘着值写，也可以连写；不带值的
选项取后面紧跟的一个参数。

```sh
tsubaki sum sha256 . --exclude=build -lold.txt
tsubaki sum hmac_sha256 . --key=secret
tsubaki sum sha256 . -svo./sum.txt     # -s -v -o ./sum.txt
```

只有两处不合惯例：

- `-e` 和 `-l` 贪婪，会一直取后面的普通参数，直到碰上下一个开关：
  `tsubaki sum sha256 . -e a b c -l list1 list2` 是三个排除项、两个列表。`-e` 在
  `-l` 前停住，因为 `excludes` 排在 `lists` 之前评估。
- 匹配不到条目的开关不是选项错误，而是被当成普通参数，最后按“文件不存在”报错。
  敲成 `--exlude=build` 时，错误出现在报告的错误块里。

对于第二条，作者认为“敲错的选项”不能再被称为一个选项，程序更不应该猜测用户的意图。
为了更好的易用性，推荐去看[Shell 补全](#shell-补全)——`-C` 打印的词表可以直接交给
shell 的补全功能。毕竟如果敲错了什么选项，结果在报告块出来的时候才收到反馈，
可不是什么好事情。

### 密钥哈希

密钥从下面两处之一取得，不能同时给：

- `--key` 接受字面字符串：参数里的字节原样当密钥，不做十六进制或转义解码，
  所以 `-k 00ff` 得到的是四字节密钥 `0`、`0`、`f`、`f`。这样用有风险：
  密钥可能泄漏在 shell 历史记录或 `/proc` 下。
- `--key-file` 从文件读，路径写 `-` 时从 stdin 读。整个流都会读完，字节原样当密钥：
  `echo secret > key` 得到的是 `secret` 再加一个换行（七个字节），不是 `secret`。
  密钥就是文件里那串字节，用 `xxd key | tail` 就能自查。文件不存在、读不了或是
  空文件，退出码 66。文件可能是在 Windows 上写的时候加 `-T`（`--text`）：
  它把文件当文本读，语义等同于 `$(cat key)` —— 每个 CRLF 折成 LF，尾部剩下的
  CR/LF 全去掉，孤立的 CR 保留，所以 `secret\r\n` 得到 `secret`，`a\r\nb\r\n`
  得到 `a\nb`。`--key` 的字面密钥不受它影响。

`-k` 和 `-K` 同时给会按命令行错误拒绝，退出码 64；`-K -` 与 `-` 输入同时出现也
一样，同一条 stdin 只能指定一次。配普通摘要时 `-k`、`-K`、`-T` 都只警告
并忽略，`-K` 指定的文件根本不会被打开。

一次运行所有文件共用一个密钥；想用两个密钥校验同一棵树，就分别跑两次。

带密钥的 BLAKE2 对密钥长度有上限：`blake2b512_mac` 最多 64 字节，
`blake2s256_mac` 最多 32 字节。超了会在打开任何文件之前按命令行错误拒绝，退出码 64；
HMAC 不限制长度。

`--key` 把密钥放在命令行上：进程运行期间，机器上的任何用户都能从 `ps` 或
`/proc/<pid>/cmdline` 读到它，shell 还会在历史文件里留一份。`--key-file` 能避开
这两处，但文件本身只和它的权限一样私密（建议 `chmod 600`）。无论哪种写法，运行
期间密钥都待在进程内存里，绝对不会留在输出结果的任何地方。不要在多用户主机上使用真正的密钥。

密钥哈希的输出与普通摘要完全一样：`<校验和> <路径>`，报告块里写的是所选算法。
没有任何字段标记某一行是密钥哈希，只有随行的那份报告块里的算法名能区分。

### 校验

`verify` 重新读取 `sum` 写出的校验和文件，并重算其中列出的每一条路径：

```sh
tsubaki verify sums.txt                 # 写出 sums.txt.verify
tsubaki verify sums.txt -o -            # 把刷新后的校验和打到 stdout
tsubaki verify sums.txt -o new.txt      # 写到 new.txt
tsubaki verify sums.txt -u sha256       # 不用文件头，改用 sha256
cat sums.txt | tsubaki verify - -u sha256   # 从 stdin 读清单
```

清单可以写成 `-`，表示从 stdin 读。`Algorithm:` 头没法在不消耗后续路径数据的前提下先
读出来，所以 `-` 清单必须配 `-u`，否则退出 64；同一条 stdin 也只能指定一次，`-` 清单
再配 `-K -` 会被拒绝。不给 `-o` 时输出按输入命名，输入是 stdin 时就是 `stdin.verify`。

算法取自文件里的 `# Algorithm:` 头，除非用 `-u`（`--use-algo`）指定。强制指定的
算法会在 stderr 上说明，并完全取代文件头，所以 `-u` 也能校验完全没有头的清单，或者
头已经过时的清单；名字不认识则退出 64。也允许指定 `none`，但那样不会计算任何哈希：
每条路径都算作 `Not hashed`，并且全部记入 unsure。清单行的读法与 `-l` 完全一致，
区别在于每一条校验和都会重算：`verify` 隐含 `--force-rescan`。

输出形状与 `sum` 相同：每个处理过的文件一行 `<校验和> <路径>`，随后是报告块。
报告里多出两个字段：

```
# Changed:           1
# Unsure:            0
```

_changed_ 表示文件里记录的校验和与重算结果不同；_unsure_ 表示这次运行没法下结论：
要么那一条写成 `<NONE> <路径>`（文件里没有可比较的校验和），要么根本没能算出哈希
（被中断、计算失败，或者算法就是 `none`）。两类路径会分别列在结果流里
对应计数的下面；写到 stderr 的那份报告不含它们。
校验和不同或 unsure **不会改变退出码**，只有
读取、写入和扫描错误才会，与 `sum` 一致——计算失败正属于后者，所以它仍然退出 1。
输出本身就是刷新过的清单，所以只要文件在此期间没有变化，对它再跑一次 `verify` 就会
得到 `Changed: 0`；在这份输出里仍是 `<NONE>` 的路径，下次再校验时归入 unsure。

`-v`、`-t`、`-k`、`-K`、`-o` 的用法与 `sum` 相同，`-u` 见上文。密钥算法必须重新提供
密钥，因为校验和文件只记录算法名，从不记录密钥。换了密钥算出的校验和完全不同，所以
给错密钥的表现是所有文件都变成 changed，而不是一条错误。声明了额外参数的动态
算法也一样：清单不记这些参数，`-u` 只给算法名，参数得在 `verify` 命令行上
重新写全。用 `none` 写出的清单会被拒绝（退出码 64），因为它没有可比较的校验和；
用 `-u` 指定别的算法可以继续，而 `-u none` 虽然也能跑（因为该选项本来就有“强制”的意思）
，但每条路径都会记入unsure。`-o` 不能指向输入文件（退出码 64），否则输入会在被读取之前先被截断。

### 比较

`cmp` 读取两份由 `sum` 写出的结果文件，报告它们之间的差异：

```sh
tsubaki cmp old.txt new.txt               # 写出 old_to_new.cmp
tsubaki cmp old.txt new.txt -o -          # 把比较结果打到 stdout
tsubaki cmp old.txt new.txt -o diff.cmp   # 写到 diff.cmp
```

两份输入都用校验和文件格式：`#` 开头的行（包括整个报告块）忽略，其余每行都必须是
`<校验和> <路径>`。不成对的裸路径和 `<NONE> <路径>` 行都没有可比较的校验和，会各记
一条错误并跳过。分隔符是两个空格，或空格加 `*`（二进制标记，不算路径的一部分）。两份
文件里最多只能有一个是 `-`（stdin）。校验和按小写十六进制比较，
所以大写写法不算变化。比较的只是校验和字符串：用不同算法（或不同密钥）写出的两份
清单没有一条能对上，于是每个路径都变成 modified，matched、moved、deleted 全都为空。

输出按差异的类别分节：

```
# tsubaki comparison result
# [!] Modified:
[!] ./chg.txt

# L = old.txt, R = new.txt
# [D] Moved,copied,merged or renamed:
# [D][1]
# [D][1][L]
[D][1][L]./mv.txt
# [D][1][R]
[D][1][R]./moved.txt

# L = old.txt, R = new.txt
# [U] Deleted or added:
# [U][L]
[U][L]./del.txt
# [U][R]
[U][R]./add.txt

# [=] Matched:
[=] ./same.txt
```

- `[!]` _Modified_（修改）：两边路径相同、校验和不同。打印的是左侧的写法。
- `[D][n]` _Moved, copied, merged or renamed_（移动、复制、合并或改名）：校验和
  相同但路径不同的条目，每个两边共有的校验和各成一组；`[D][n][L]` 列左侧路径，
  `[D][n][R]` 列右侧路径。只在一边出现的校验和不成组，那些路径归入删除/新增。
- `[U]` _Deleted or added_（删除或新增）：只出现在左侧（`[U][L]`）或只出现在右侧
  （`[U][R]`）、且在另一边没有同校验和路径的条目。
- `[=]` _Matched_（相同）：两边路径相同、校验和也相同。
- `[E]` _Error messages_（错误）：只在记录过问题时出现——某行没有校验和、`-c`
  无法把路径规范化，或者清单读取失败。比较会继续进行，此时的退出码是 1。

同一份清单里同一个路径重复出现、且校验和相同，只比较一次；同一个路径重复出现但
校验和不同，会按命令行错误拒绝（退出码 64），因为没有一个唯一的值可以比较。

不给 `-c` 时，路径按原样逐字比较，所以 `./a.txt` 和 `b/../a.txt` 是两个不同的路径。
给了 `-c`（`--canonical`）时，两边路径先变成绝对路径、解析软链接并规整分隔符，
因此指向同一文件的不同写法可以匹配上。
规范化要求路径存在：已删除的文件没法规范化，所以会保留未被规范化的路径并参与比较，
同时记录一条错误。

不给 `-o` 时，结果写到当前目录下的 `<左文件名去扩展名>_to_<右文件名去扩展名>.cmp`
（`old.txt` 和 `new.txt` 得到 `old_to_new.cmp`），并在 stderr 上提示这个文件名。
`-o -` 写往 stdout。`-o` 不能指向任何一份输入（退出码 64），因为两份清单都是在输出
打开之后才读的。各节之间重复出现的 `# L = ..., R = ...` 行标明两份输入；
开头还会往 stderr 打一份，这样结果写进文件时也能在终端上看到比的是哪两份。

`cmp` 不做任何哈希、遍历或扫描：它只读两个文件，所以下文的“中断”处理不适用于它，
`Ctrl-C` 会直接按默认动作结束进程。

### Shell 补全

`-C`（`--completions`）打印一行后退出：全部选项名（内建的，以及 provider 自己声明的）、
全部内建算法、全部已加载的 provider，以空格分隔。和 `-a` 一样，它不需要子命令。

```sh
tsubaki -C                        # 那一行，空格分隔
tsubaki -C | tr ' ' '\n' | sort   # 一个词一行
```

这一行是给 shell 的词表补全用的。bash 里：

```sh
complete -o default -W "$(tsubaki -C)" tsubaki
```

引号是命令的一部分。少了它，shell 会把输出按空格切成一个个参数，`complete -W` 只留
其中一个，结果只有某一个算法名补得出来。`-o default` 让文件名补全继续生效，而 `sum`
和 `cmp` 收的绝大多数参数正是路径。

包成函数就随时能刷新：

```sh
tsubaki_completion() {
    complete -o default -W "$(tsubaki -C)" tsubaki
}
tsubaki_completion
```

函数体在最后一行的调用处执行，每个 shell 一次，所以词表是一份快照：装好新 provider
后再跑一遍 `tsubaki_completion`，不用开新 shell 就能把它补进去。
`TSUBAKI_DYNAMIC_PROVIDER_PATHS`（见[动态算法](#动态算法)）要在调用之前导出，
因为扫描走的就是这条路径，别处不看。

zsh 没有 `complete`，用 `compadd` 加 `_files` 顶上同样的位置：

```zsh
_tsubaki() {
    local words="$(tsubaki -C)"
    compadd -- ${(s: :)words}
    _files
}
compdef _tsubaki tsubaki
```

`--` 不能省，因为表里的词以 `-` 开头。

表里没有的东西：`--verify`（内部开关），以及任何位置上下文——它就是一张平表，
在每个位置都全量给出。子命令名也在表里，所以在选项之后同样会补出来；`--text` 和
`--thread` 这种共享前缀的词，要按第二次 `<TAB>` 才会列出来。

## 输入

命令行上的文件与目录直接扫描。列表文件（`-l`，或 `-` 从标准输入读）逐行解析，
每一行都是 `<校验和> <路径>` 这一种形式，没有第二种。单独的 `-` 和 `-l -` 是
同一件事的两种理解：前者把它当输入源，后者把它当 `-l` 的文件名，读到的都是 stdin。
每行按 coreutils 的规则读取，所以路径自己的首尾空格会被保留：

- 空行、第一个非空白字符是 `#` 的行忽略；
- 以 `<NONE>` 加一个空白字符开头的行，取分隔符后面的路径；
- `<校验和> <路径>` 形式的行原样保留，输出中打 `# Kept: <路径>` 加原行；
  只有给了 `--force-rescan` 才会按路径重算；
- 其它行不是清单行：作为错误报出来并跳过。

被保留的行与计算过程解耦：不参与哈希，也不出现在报告的计数里。它是在读列表时
就写进结果流的，所以可能夹在算完的行中间。

列表里的每一行都当作文件处理。行里写目录会被拒掉，不会展开；只有命令行上的目录
参数才会被遍历。以 `#` 开头的行即使本意是路径也算注释，所以名字以 `#` 开头的文件
要写成 `./#名字` 或绝对路径。

校验和可以是任意宽度，低到一个十六进制字符也行：每一行的形状都一样，校验和不会
被误当成路径，也就不需要靠长度去猜。路径就是第一个空格之后的全部内容，所以可以
含空格。

因此，一份只有路径的文件不是清单，会被当作错误报出来，而不是猜着读。要哈希它，
给每行加 `<NONE> ` 前缀，或者把路径放到命令行上：

```sh
sed 's/^/<NONE> /' paths.txt | tsubaki sum sha256 -
xargs -d '\n' tsubaki sum sha256 < paths.txt   # GNU xargs，能保住空格
```

`$(cat paths.txt)` 也能用，但只在没有路径含空格时成立：shell 会在 tsubaki 看到
之前按空白把结果拆开。

coreutils 用两个空格、或空格加 `*`（`sha256sum --binary` 的二进制标记）分隔校验和
与路径；那个 `*` 会被丢掉，永远不算路径的一部分，两种写法读出来完全一样。`sum`
写的也是两个空格、从不写标记，所以它的输出能原样读回，以 `*` 开头的路径也不例外。

读取时按 coreutils 的规则拆行：行首空白跳过，校验和到第一个空格或制表符为止，
然后吃掉一个空白字符；只有当后面还剩一个以上字符、且该字符是空格或 `*` 标记时，
才再吃掉一个。此后的全部内容就是路径，所以名字自己的首尾空格被保留，第三个空格
属于名字。单空格行与双空格行读法相同，只是它的路径不能以 `*` 开头：这种路径要写成
`./*名字`、绝对路径，或者用两个空格。解析前会去掉行尾的一个 `\r`，所以 CRLF 清单
和 LF 清单读法一致。

名字里含换行、回车或反斜杠时，写法和 coreutils 一致：整行以 `\` 开头，名字里这三个
字符变成 `\n`、`\r` 和 `\\`，这样的行也能原样读回。其它 `\x` 序列会让整行无效。

`<NONE> <路径>` 也能作为输入，所以一次运行的输出可以直接用 `-l` 喂回去，只重做
那些没有计算校验和的文件。

排除项写的是路径，不是模式：它跟目录遍历中遇到的每个条目逐一比较，所以
`-e build` 会排除那棵目录树，而 `-e '*.tmp'` 什么都匹配不到。它只作用于目录扫描：
命令行上直接给出的文件、或列表里读进来的文件，即使被排除也照样计算，因为程序
认为这两个途径属于“显式指定”。若排除项就是被扫描的目录本身、或它的某个上级目录，
则什么都匹配不到，会被静默忽略——要排除就排除子目录。也别用 `-e` 去“排除”一个
同时作为输入传进来的目录：不想要它，就别在命令行上写它。

命令行上或列表里显式给出的设备/FIFO 会被当作流打开并读完。所以 `/dev/null` 算出
的是空内容，`/dev/stdin` 算管道送来的东西，进程替换的 `/dev/fd/N` 也能用。这类流
可能阻塞或者永远不结束，见“中断”。socket 读不出内容，显式给出就是错误。目录遍历
则相反，只交出普通文件：遍历中遇到的设备、FIFO 或 socket 会被静默跳过，连一条错误
都不记，所以 `sum sha256 ~` 不会卡在别人留下的管道上。

路径不做去重：同一个路径写两次就处理两次。

稀疏文件按逻辑长度计算：空洞读出来就是零，所以只占几 MB 的 1 TB 稀疏镜像仍要读满
1 TB。

## 输出

结果默认写到 stdout，可用 `--output` 改到文件。结果流开头是一行
`# tsubaki checksum result`，之后每个文件一行：

```
<校验和> <路径>
```

两个字段之间是两个空格，与 coreutils 清单一致；`*` 二进制标记只在输入时接受，
永远不会写出来。

（`cmp` 写的是 `# tsubaki comparison result` 和它自己的各节，见
[比较](#比较)。）

行的顺序是完成顺序，不是输入顺序，所以多线程下每次运行的顺序都可能不同。路径按
扫描器产出的原样打印：`.` 下面找到的条目带 `./`，列表里的条目则按原写法。

没算过的文件——被中断的、或者算法是 `none` 的——写成 `<NONE> <路径>`。已经通过
扫描、但打开/读取/哈希失败的文件也写成 `<NONE>`，并计入 Failed。

不存在的路径在取任务时就会被过滤掉：没有输出行，也不进下面任何一个计数，只往
错误块里加一条记录，但它一样会让退出码变成 1。列表里写的目录也按同样方式拒绝。

随后是报告块，每行都以 `#` 开头：

```
#
# ---------- Summary ----------
# Algorithm:         sha256
# Processed:         3
# Hashed:            3
# Failed:            0
# Not hashed:        0
# Duration:          1.23456 seconds
# Errors:            0
```

`Algorithm` 是本次运行选定的算法；它不会变，所以被打断的运行也照样写着当时在用的
算法。`Duration` 量的是从启动工作线程到 join 结束，不含参数解析和扫描准备。

`Processed` 等于 `Hashed + Failed`，未计算校验和的文件不计入；被保留的行和跳过
的路径也不算在内。

`# Errors:` 条数行总会打印，即使为 0 也在。被打断的运行会在条数下面多出一个 `#`
分隔行和一行 `# Warning: The process was interrupted halfway through.`；记录过至少
一条错误时，后面还会跟一个 `# Error messages:` 块，每条一行
`# Value: / Message: / Operation:`：

```
# Errors:            2
#
# Error messages:
# Value: 2, Message: No such file or directory, Operation: determining the file type of plain.txt
```

错误不一定来自计算失败：不存在的输入路径、打不开的列表文件、不存在的排除项等
非阻断性错误都会记在这里，所以一次运行的 `Failed` 可以是 0、退出码却是 1
（而且不存在的排除项虽然报错，扫描本身照常继续）。

用 `--output` 时，报告块还会额外写一份到 stderr（不含逐条错误信息），这样结果
进文件、简短摘要在终端上也会输出一份。

进度指示只写 stderr，不混进结果流。

写入失败——磁盘写满、描述符损坏、文件所在挂载点被移除——退出码是 `73`，结果流在
运行结束时统一检查。若结果写往读端已关闭的管道，进程会被 `SIGPIPE` 按默认动作
直接结束（shell 报 141），走不到 `73`。

### 报告字段

这些字段名是固定的：不会改名、删除或改变含义。`Changed` 和 `Unsure` 由 `verify`
写出，其余七个两个子命令都写。

| 字段         | 含义                                      |
| ------------ | ----------------------------------------- |
| `Algorithm`  | 本次运行使用的算法；即使被中断也会写      |
| `Processed`  | `Hashed + Failed`                         |
| `Hashed`     | 本次运行算出校验和的文件数                |
| `Failed`     | 打不开、读不了或算不出的文件数            |
| `Not hashed` | 没有校验和的文件：被中断，或算法是 `none` |
| `Duration`   | 工作线程花掉的秒数，十进制小数            |
| `Changed`    | 与清单中记录的值不同的路径数              |
| `Unsure`     | 无法判断的路径数：不存在、读不了或没算过  |
| `Errors`     | 记录到的错误数；这一行总会写              |

块内的小标题同样固定：`Changed files:`、`Unsure files:`、`Error messages:`，
每条错误写成 `Value: <数字>, Message: <文本>, Operation: <文本>`。

其余都只是排版而不是契约：冒号后的空格、`Duration` 的写法，以及块上方结果行的
先后顺序。

## 退出状态

| 退出码 | 含义                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | 没有记录任何错误；`verify` 会把 changed/unsure 报出来、`cmp` 会把所有差异报出来，但都不当作错误                                                                                                                                                                                                                                                                                                                     |
| `1`    | 记录过至少一条错误：校验失败、不存在的路径、打不开的列表文件、不存在的排除项；`cmp` 还会把没有校验和的清单行、`-c` 无法规范化的路径、清单读取失败记为错误                                                                                                                                                                                                                                                           |
| `64`   | 命令行无效：未知子命令、未知算法、密钥算法没给密钥或密钥过长、`-k` 与 `-K` 同时给、`-K -` 与 `-` 输入同时出现、线程数不对，或者有多余参数；`verify` 还会在没有 `-u` 时对没有 `Algorithm:` 头的输入、对没配 `-u` 的 `-` 输入、对用 `none` 写出的清单、对未知的 `-u` 名字、以及输出指向输入文件的情况返回 64；`cmp` 在两份清单都是 stdin、输出指向其中一份清单、或同一份清单里同一路径带着不同校验和重复出现时返回 64 |
| `66`   | `--key-file` 读不了、密钥文件里没有密钥，`verify` 的输入不存在或是个目录，或者 `cmp` 的清单读不了                                                                                                                                                                                                                                                                                                                   |
| `70`   | 启动即失败：provider 声明需要参数，却没有一份可用的参数脚本                                                                                                                                                                                                                                                                                                                                                         |
| `73`   | `--output` 指定的文件打不开，或者输出流错误。                                                                                                                                                                                                                                                                                                                                                                       |
| `130`  | 运行被 `Ctrl-C` 打断                                                                                                                                                                                                                                                                                                                                                                                                |
| `250`  | 按下五次 `Ctrl-C`，进程当场中止，不保证输出结果的完整性。                                                                                                                                                                                                                                                                                                                                                           |
| `255`  | 有异常逃出了 `main()`，说明存在开发者未考虑到的 bug，可以提交 issue。                                                                                                                                                                                                                                                                                                                                               |

`--help` 和 `--version` 的退出码是 `0`。`64`、`66`、`70` 和 `73` 取自 sysexits
的 `EX_USAGE`、`EX_NOINPUT`、`EX_SOFTWARE` 和 `EX_CANTCREAT`；`130` 就是 shell 的
`128 + SIGINT`；`250` 与意外异常使用的 `255` 差一格，两者不会混。

## 中断

第一次 `Ctrl-C` 会让本次运行停下来。工作线程在处理下一个文件之前就停下：
还没开始的文件照样被取出，写成 `<NONE>` 并计入 `Not hashed`，因此报告能为扫描器
产出的每个文件留个交代。已经进入计算函数的文件不会被丢掉；如果那是设备或 FIFO，
就意味着它可能一直读到 EOF。而卡在 `open()` 或无限读取里的工作线程根本回不到检查点，
所以一次 `Ctrl-C` 停不下它。

这让中断可以续算：把那次的结果文件直接当 `-l` 的输入喂回去，已经带校验和的行原样
保留，`<NONE>` 行重新计算。报告块以 `#` 开头会被忽略，所以结果文件不用先过滤。
被中断的运行即使没有任何失败，退出码也是 `130`，所以 `1` 仍然代表真的出错。

累计按下五次 `Ctrl-C` 则彻底放弃：处理函数往 stderr 写一行固定消息，并当场调用
`_Exit(250)`。此后什么都不再刷出，所以输出可能没有报告块，计数也一并丢失。
